# CLAUDE.md

Guidance for Claude Code sessions in this repository.

## What this repo is

Fork of [NMadhub/trakr-newton-locomotion](https://github.com/NMadhub/trakr-newton-locomotion): an
Isaac Lab v3.0.0-beta task package that trains the Trakr quadruped on the Newton physics backend, plus
an NVIDIA Brev Launchable kit under `brev/` that turns a fresh L40S VM into a workshop node. The task
code is kept as close to upstream as possible; everything Brev-specific lives in `brev/`.

| Path | Role |
|---|---|
| `trakr_locomotion/` | Isaac Lab task package (env, rewards, PPO config). Upstream code, two small additions (below). |
| `scripts/train.py`, `scripts/play.py` | runpy wrappers around Isaac Lab's rsl_rl scripts |
| `setup.sh`, `patches/` | upstream: pins newton 1.0.0 / mujoco 3.5.0 / mujoco-warp 3.5.0.2, Isaac Sim 6.0 compat patches |
| `assets/`, `exported/` | robot USD and the shipped policy (plain git objects in this fork, not LFS) |
| `brev/launchable-setup.sh` | the 10 lines pasted into the Brev Launchable; clones this repo, runs `brev/brev-setup.sh` |
| `brev/brev-setup.sh` | full node setup: XFCE/noVNC desktop, Isaac Lab + pip Isaac Sim, this repo's `setup.sh`, viser, helper scripts, warm-up |
| `brev/LAUNCHABLE.md` | console steps, GPU choice, launch parameters, verified results, troubleshooting |
| `WORKSHOP.md` | attendee guide (also built to `brev/docs/Trakr-Newton-Workshop-Guide.pdf` by `brev/docs/build-guide.sh`) |
| `outputs/` | git-ignored; clips pulled from instances |

## Differences from upstream (keep them minimal)

- `scripts/*.py`: `sys.path.insert(0, dirname(target))` so Isaac Lab's `import cli_args` resolves.
- `trakr_locomotion/rough_env_cfg.py` (+ a call in `flat_env_cfg.py`): optional visualizer cap. Active
  only when `TRAKR_VIZ_WORLDS` is set (the helpers set it, with `TRAKR_NUM_ENVS`). It builds
  `NewtonVisualizerCfg`/`ViserVisualizerCfg(max_worlds=N)` and aims the camera at the first N env
  origins. With the variable unset the configs equal upstream.
- `.gitattributes`: no LFS, so Launchable clones do not consume LFS bandwidth.
- Do not patch Isaac Lab beyond what upstream `setup.sh` does. The user's stated preference is to stay
  true to the original repo.

## How the kit is tested

There is no local GPU. Deploy the Launchable (or any Brev L40S VM), then work over SSH:

```bash
brev refresh                                   # writes ssh config entries
ssh <instance-name> 'tail -f /var/log/trakr-brev-setup.log'   # ends with "=== DONE"
```

Iterate with `git push`, then on the node `git -C ~/newton_trakr_brev pull && sudo -E WARMUP=0 bash
~/newton_trakr_brev/brev/brev-setup.sh` (idempotent, about 1 minute on a warm node, keeps a running
desktop). Helper scripts are regenerated by the setup script, so edit them in `brev-setup.sh`, not on
the node. Task-package edits are live immediately (`pip install -e`).

Verified on Crusoe `l40s-48gb.1x` and documented in `brev/LAUNCHABLE.md`: setup ~10 min, 2048-env
training 0.46 s/iteration, all helpers pass, rough-terrain task fails on Newton (Isaac Lab contact
sensor on generated terrain).

## Facts that cost time to learn

- Isaac Lab runs Newton **kitless** here: no Kit/RTX start, a launch takes about a minute. Isaac Lab's
  `--video` flag (needs Kit render) does not work; the recorder uses ffmpeg x11grab + NVENC instead.
- `--visualizer_max_worlds` is ignored in kitless mode (written to a Kit settings store the
  simulation context never reads). Hence the env-config cap above.
- Isaac Lab's Hydra wrapper strips `--num_envs` from `sys.argv` before configs are built, and
  `train.py` applies it after `__post_init__`; hence `TRAKR_NUM_ENVS`. `configclass` has no class
  attributes: check `__dataclass_fields__`, not `hasattr`.
- Both viewers draw every env by default; 2048 envs in the GL viewer means 2 FPS and 10 s/iteration.
- Isaac Lab's `play.py` does not pick up `exported/` by itself; helpers pass `--checkpoint`.
- uv needs `--index-strategy unsafe-best-match` for the isaacsim wheel (a dependency is pinned to a
  version only PyPI has while the name also exists on NVIDIA's index).
- Xorg `BusID` must include the PCI domain when it is not 0 (`PCI:0@2:1:0` on Crusoe).
- NVENC rejects the 64x64 probe frame; probe with 320x240 or larger.
- Over SSH, `pkill -f <pattern>` kills the SSH shell itself if the pattern appears in its command
  line: use `pkill -f "[p]attern"`. The setup log is appended across reruns, so watchers must scope
  to the last `=== Trakr/Newton Brev setup` block or look for new files, not old "saved" lines.
- Never kill a viewer window the user is watching on the desktop, and never start two recorders at
  once (same-second file names corrupted a clip; the recorder now refuses and adds a pid suffix).

## Conventions

- Commit messages: imperative summary line, then what was seen on the node that motivated the change.
- Keep `brev/LAUNCHABLE.md` in sync with any helper or parameter change; it is the operator's source.
- Attendee-facing text: `WORKSHOP.md` in the repo and the short `~/WORKSHOP.md` written by
  `brev-setup.sh` (it contains the generated VNC password, so it stays on the node).
- Clips pulled from instances go to `outputs/{play,train}/` (git-ignored).
